# Sparse evidence development cases

These fictional cases exercise the production refinement runner after a user
supplies concrete details for a sparse bullet. They are development examples,
not reserved validation cases, customer resumes, or human preference results.

Each case supplies an original bullet, prior conversation, confirmed evidence,
and a supported authored candidate for factual-review calibration. Live smoke
runs generate a new candidate; factual approval alone does not establish better
writing. Review the generated text for the intended contribution as well.

- `sparse-email-confirmed-tasks`: link checks and scheduling approved drafts make
  campaign assistance specific, without claiming strategy ownership or measured
  conversion gains.
- `sparse-chinese-unknown-numbers`: confirmed classification and documentation
  tasks support a qualitative Chinese bullet. Unknown volume, time savings, and
  efficiency must stay unknown.
- `sparse-warehouse-confirmed-workload`: an explicitly confirmed calculation
  supports approximate monthly shipment-record workload. It does not establish
  shipments delivered, unique customers, savings, fewer delays, or leadership.
- `sparse-spoken-chinese-english-bullet`: a conversational Chinese account gives
  concrete spreadsheet checks and handoff without an editing instruction. The
  original English bullet anchors output language; unknown savings stay unknown.

Prior model drafts deliberately contain unsupported leadership or result claims.
Those drafts are context, not evidence. Confirmation timestamps are fixed fixture
values, not records of real user actions. The workload estimate is generated by
`estimateImpact` and checked by `normalizeConfirmedEstimates`, preserving its
unit, monthly period, and approximate status.

Validate the corpus without making model calls:

```sh
npm run eval:refinement -- --cases eval/content/sparse-evidence-cases.json
```

Run one case through generation and independent factual review:

```sh
npm run eval:refinement -- --live --smoke \
  --cases eval/content/sparse-evidence-cases.json \
  --case sparse-email-confirmed-tasks \
  --out eval/content/sparse-evidence-followup/email.json
```

Repeat with the other case IDs and distinct output filenames. Explicit `--out`
paths refuse overwriting existing results and create parent directories. Omitting
`--smoke` runs factual-review calibration on the authored candidates; omitting
`--cases` and `--out` preserves the original corpus and output defaults. Saved
outputs include the corpus hash, selected case IDs, Git revision, and code hashes
to identify the exact inputs and implementation used.

## First live results

The four separate runs in `sparse-evidence-followup/` completed generation and
independent factual review using DeepSeek V3.2. Each used two model calls:

| Case | Time | Observed output |
| --- | ---: | --- |
| Email tasks | 7.7 s | Link checks and scheduling drafts after approval; no conversion claim |
| Chinese unknown numbers | 12.2 s | Classification, operating steps and use by new colleagues; no numbers |
| Chinese spoken account / English source | 10.6 s | English checks, missing delivery-date records and coordinator handoff |
| Confirmed workload | 17.2 s | Approximately 500 shipment records monthly and missing-status follow-up |

These results demonstrate evidence use and factual-review completion for the
authored examples. They do not establish real speech-recognition accuracy,
human preference, population uplift, or hiring outcomes. Browser voice testing
uses simulated recognition callbacks; live model testing uses text narratives.
